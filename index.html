How it's built

Built to make mistakes impossible, not just unlikely.

This was built mostly solo, with AI doing most of the actual typing, which meant no full team's code review to catch every mistake. So the architecture is designed so entire classes of security bugs can't be expressed at all. Here's the one that matters most: how one company's data stays away from another's.

That's one guardrail out of several. The same construction applies everywhere a mistake would matter:

Permissions
Every check runs through a single policy module; comparing roles inline anywhere else is a lint error, not a style preference.
Primitives
Raw SQL, cryptography, and random-number generation are banned outside a handful of files, audited by hand, one primitive per file.
Audit log
Every action that changes something writes a hash-chained entry, so a write can't be quietly altered after the fact.

It isn't flawless. Real bugs have been found and fixed this way, including a caching issue that briefly showed one account's data after switching users. That's exactly why this is live at an early, rough stage instead of sitting private until it feels finished.

Questions

Frequently asked

Is Rinavai free to use?

Rinavai offers a free way to get started. You can create an organization, invite your team, and explore the core collaboration features. Available plans and limits are managed directly from your organization settings and may evolve as the product develops.

Is there an iOS app?

An Android app is already available and can be downloaded directly from Rinavai. The iOS app is currently in development and will be available in a future release.

How is my organization's data kept separate from other companies using Rinavai?

Rinavai is built as a multi-tenant application with organization-level data isolation. Every authenticated request carries an organization context, and access to workspace resources is scoped against that context before data is returned or modified. Authorization is enforced independently of the UI, so users cannot access resources belonging to another organization simply by changing an ID or request parameter.

Can I self-host Rinavai?

Rinavai is currently offered as a hosted service and is not distributed as a self-hosted package. This allows us to manage infrastructure, deployments, security updates, and the multi-tenant environment centrally while keeping the product consistent for all organizations.

Is this production-ready?

Rinavai is live and designed around production-oriented requirements rather than being a simple prototype. It includes organization-level tenant isolation, centralized authorization checks, authentication and session security, audit logging, and controlled access to workspace resources. The platform is actively evolving, so new capabilities and refinements are continuously being introduced.
