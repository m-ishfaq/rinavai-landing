How it's built

Built to make mistakes impossible, not just unlikely.

This was built mostly solo, with AI doing most of the actual typing — which meant no full team's code review to catch every mistake. So the architecture is designed so entire classes of security bugs can't be expressed at all. Here's the one that matters most: how one company's data stays away from another's.

That's one guardrail out of several — the same construction applies everywhere a mistake would matter:

Permissions
Every check runs through a single policy module; comparing roles inline anywhere else is a lint error, not a style preference.
Primitives
Raw SQL, cryptography, and random-number generation are banned outside a handful of files, audited by hand, one primitive per file.
Audit log
Every action that changes something writes a hash-chained entry — a write can't be quietly altered after the fact.

It isn't flawless. Real bugs have been found and fixed this way — including a caching issue that briefly showed one account's data after switching users. That's exactly why this is live at an early, rough stage instead of sitting private until it feels finished.
